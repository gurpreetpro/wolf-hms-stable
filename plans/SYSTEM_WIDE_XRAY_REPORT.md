## Section 1 — Exact Root Cause of `/ward` “Failed to record consumable” & “NEWS2 ? - Unknown”

### 1.1 `Failed to record consumable`

Frontend (`client/src/components/NursePatientProfile.jsx:327-344`) posts `{ admission_id, patient_id, consumable_id, quantity, notes }` to `POST /api/nurse/consumables` and converts **any** thrown error into the string `Failed to record consumable`. That message therefore hides four different failure modes:

| # | Execution step | File / line | Failure mode on prod | Result |
|---|---|---|---|---|
| 1 | `SELECT name, price FROM ward_consumables WHERE id=$1` | `server/controllers/nurseController.js:270` | `ward_consumables` missing or `price` absent | 500 → generic toast |
| 2 | `UPDATE ward_consumables SET stock_quantity = stock_quantity - $1 WHERE id=$2 AND hospital_id=$3` | `nurseController.js:275` | `stock_quantity` absent, or `req.hospital_id` undefined → parameter type cannot be inferred | 500 |
| 3 | `INSERT INTO patient_consumables (admission_id, consumable_id, item_name, quantity, unit_price, total_price, notes, used_by, hospital_id)` | `nurseController.js:278-282` | **`patient_consumables.admission_id` is INTEGER while prod `admissions.id` is UUID** → `column "admission_id" is of type integer but expression is of type uuid` (SQLSTATE 42804); `used_by` FK to `users` with a UUID/undefined user | 500 (most likely cause) |
| 4 | `SELECT patient_id FROM admissions WHERE id = $1` then `addToInvoice(...)` | `nurseController.js:285-289` | `addToInvoice` runs **after** the consumable insert and **outside any transaction**; any billing-table drift throws and the client reports “Failed to record consumable” even though the row was written | 500 + double-charge risk on retry |

**Secondary defect (same file, read path):** `getPatientConsumables` (`nurseController.js:299-306`) selects `pc.*` and joins `users u ON pc.recorded_by = u.id`, while the write path only sets `used_by`. On any schema where `recorded_by` is absent the usage-history tab 500s as well.

**Local-schema evidence (proxy for prod):** `patient_consumables.admission_id` is `integer`; `admission_id` is an FK to `admissions(id)`. Because prod `admissions.id` is `uuid`, the same INSERT cannot succeed there unless prod’s column was widened — exactly the class of defect Pass 2 enumerates (78 integer `*_id` columns).

### 1.2 `NEWS2 ? - Unknown`

`client/src/components/ward/BedCard.jsx:13-15,92-94` renders:

```jsx
const news2Score = admission.news2Score;
const news2Risk  = admission.news2Risk || 'Unknown';
...
{news2Score !== null ? news2Score : '?'} - {news2Risk}
```

The ward bed/admission payload never carries `news2Score`, `news2Risk` or `news2Color`. `undefined !== null` is `true`, so the score renders empty and the risk falls back to `Unknown` (when the API sends `null`, the literal `?` is shown). **There is no backend NEWS-2 computation for ward admissions** — the only server-side scorer is the Bucket-C `/api/ews/scores` sweep, which the ward screen does not call.
